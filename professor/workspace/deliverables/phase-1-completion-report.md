## Contract Status

The task package retains the common fields required by Prompt-gen and supports `READY` and `NEEDS_CONTEXT` with conditional missing-context requirements. READY tasks now require a non-empty scope, questions, evidence requirements, safety constraints, and deliverable sections.

The result envelope retains `task_id`, `agent`, `result_type`, `status`, `summary`, `findings`, `evidence`, `limitations`, `acceptance_criteria_check`, and `recommended_next_steps`. Typed finding fields support research, code review, architecture, adversarial review, and validation payloads. Code-review findings preserve source location, revision, behavior, trigger, mechanism, root cause, impact, remediation, regression test, evidence references, and limitations. Ordered line ranges are enforced by the local supplemental validator because Draft 2020-12 JSON Schema does not compare two property values.

Schemas are intended contracts and local validation artifacts. They are not automatically enforced by OpenCode during live delegation; Professor must inspect returned results and preserve partial, blocked, failed, or disputed status.
