### Target Neo4j Organizational Topology
Ensure the Neo4j graph enforces this exact hierarchy:
`(:Domain {id, name}) <-[:BELONGS_TO]- (:GitOrg {id, name}) <-[:BELONGS_TO]- (:Repository {id, name, repo_type}) <-[:CONTAINS]- (:SourceFile {path}) <-[:CONTAINS]- (:ASTNode {id, name, start_line, end_line})`

where `repo_type` is an Enum: `MICROSERVICE`, `SHARED_LIBRARY`, `APPLICATION`.

### Requirements to Implement

#### 1. Ingestion Adapter (`src/investigation_agent_platform/infrastructure/evidence/code/layer3/ingestor.py`)
Implement `Layer3Neo4jIngestor`:

- `async def seed_organizational_topology(self, domain_id: str, domain_name: str, git_org_id: str, repo_profile: CodeProfile, repo_type: str) -> None`:
  - Idempotently `MERGE` the `Domain`, `GitOrg`, and `Repository` nodes and their `BELONGS_TO` edges in Neo4j.

- `async def ingest_repository_ast_symbols(self, repository_id: str, file_path: str, symbols: list[CodeSymbol], tenant_id: str) -> None`:
  - Take `CodeSymbol` outputs directly from `TreeSitterParser` for a given file.
  - Execute idempotent Cypher queries (`MERGE`) to create/update `(:SourceFile {path: file_path})` attached to `(:Repository {id: repository_id})`.
  - Create `(:ASTNode)` nodes for each symbol and establish `(:SourceFile)-[:CONTAINS]->(:ASTNode)` or `(:ASTNode)-[:PARENT_OF]->(:ASTNode)` based on `parent_symbol`.

- `async def ingest_graphify_artifact(self, repository_id: str, artifact_path: Path, tenant_id: str) -> None`:
  - Parse a `call_graph.json` artifact generated by `CodebaseGraphPipeline.export_graphify_format()`.
  - Batch-upsert nodes and edges (`DEFINES`, `CONTAINS`, `CALLS`, `REFERENCES`, `ACCESSES_TABLE`) into Neo4j, anchoring root `source_file` nodes to `(:Repository {id: repository_id})`.

#### 2. Domain Resolver (`src/investigation_agent_platform/infrastructure/evidence/code/layer3/resolver.py`)
Implement `Layer3DomainResolver`:

- `async def resolve_symbol_to_domain(self, tenant_id: str, repository_id: str, file_path: str, line_number: int) -> dict`:
  - Execute an optimized Cypher query starting at the `ASTNode` matching `file_path` where `start_line <= line_number <= end_line`.
  - Traverse upward: `(n:ASTNode)-[:CONTAINS|DEFINES*1..3]-(f:SourceFile)-[:CONTAINS]-(r:Repository)-[:BELONGS_TO]->(g:GitOrg)-[:BELONGS_TO]->(d:Domain)`
  - Return a dictionary containing:
    - `symbol_name`: Name of the failing function/class
    - `file_path`: Relative file path
    - `repository_id`: Repository identifier
    - `repo_type`: `SHARED_LIBRARY` | `MICROSERVICE` | `APPLICATION`
    - `git_org_id`: Git organization
    - `domain_id`: Resolved owning business domain
    - `domain_name`: Resolved domain name

- Fallback Handling:
  - If line number falls outside indexed AST nodes, resolve at the `SourceFile` or `Repository` level.
  - If `tenant_id` is unauthorized, raise `SecurityPolicyViolationException`.
  - If no domain node is linked, return `domain_id="UNATTRIBUTED"`.

Write complete, async Python code using `neo4j` (AsyncDriver), type hints, structlog logging, and OpenTelemetry tracing (`opentelemetry.trace`) matching the conventions in `intelligence.py` and `git.py`.
