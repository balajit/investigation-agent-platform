# Proof Publication Commit — C1+C2 Design v1.0 (Review Stage C)

> Status: AUTHORIZED under conditional approval 2026-10-24 (Review Stage C1+C2; guardrails: dev stack only, report before merge, stay non-authoritative, alembic auto-approved for dev). This document is the design record: schema, commit protocol, writer audit, RLS posture, test plan, and residuals. The kernel stays non-authoritative: no production verify/conclude path calls the commit service; production files are not modified except additive ORM models plus migration-head test expectations.

## 1. Decisions

C1 persists the derivation graph and connects composition/invalidation to persisted derivations; invalidation closure itself stays pure (recomputed from stored nodes on every read, never stored as state that could go stale). C2 adds the persisted publication commit and a single-transaction check-then-commit that binds context, proof validity, and policy at one linearization point, with lifecycle projections (hypothesis status, finding, conclusion) written inside the same transaction. Competing commits serialize on the hypothesis row (`SELECT ... FOR UPDATE`) plus a version-guarded update; any context movement between evaluation and commit denies with `STALE_CONTEXT` instead of publishing a mixed snapshot. Loop-evidence appends racing a commit are a documented residual: only competing commits serialize against each other, because serializing against the live loop would require touching production write paths, which the non-authoritative guardrail forbids.

## 2. Schema (migration 033, dev only)

`proof_derivations`: one row per accepted derivation node — `tenant_id`, `investigation_id` (FK investigations CASCADE), `derivation_id` (unique per tenant), `proposition_id`, `context_id`, `rule_id`, `rule_version`, `premise_ids` JSONB, `depends_on` JSONB, `route` (`mandatory` or `alternative:<group>`), timestamps; indexes on `(tenant_id, investigation_id)` and `(tenant_id, derivation_id)`. `proof_publication_commits`: one row per accepted commit — `tenant_id`, `investigation_id` (FK CASCADE), `derivation_id`, `context_id`, `gate_policy_version`, `reconciliation_state`, `decision` (`COMMIT`), unique `(tenant_id, derivation_id, gate_policy_version)` so a derivation commits at most once per policy version; indexes on `(tenant_id, investigation_id)`. Both tables get the standard tenant policy (`ENABLE + FORCE ROW LEVEL SECURITY`, `tenant_isolation` on `tenant_id = current_setting('app.tenant_id', true)`), following the 012 pattern; the review-noted missing policies on older analyzer tables are unchanged and out of scope.

## 3. Commit protocol (single transaction)

Open one `rls_session` transaction and, in order: lock the hypothesis row (`SELECT ... FOR UPDATE`) and deny `STALE_VERSION` on version mismatch; recompute the evidence-set digest (sha256 over sorted per-tenant fingerprints for the investigation) and deny `STALE_CONTEXT` on mismatch; list unresolved contradictions (`resolution_status = UNRESOLVED`) and deny `CONFLICT_UNRESOLVED` unless the caller passes explicit adjudication (adjudication is an explicit input, never a default: callers pass `reconciliation_adjudicated=True` even for an empty conflict set); run `check_certificate` (must be `VALID` — a bare `VERIFIED` without a valid current derivation is never authorized, K13) and `decide_publication` (must be `COMMIT`); persist derivation nodes; insert the commit row; project lifecycle (version-guarded hypothesis status advance from `SUPPORTED`/`UNDER_INVESTIGATION`, finding insert, conclusion insert). Any failure rolls the transaction back with zero partial rows. Route semantics: `single` commits one derivation; `all` requires every mandatory route `VALID` (`compose_conjunction`); `any` requires one surviving `VALID` route (`compose_alternatives`, K5). Policy stability (K12): the same derivation under a new `gate_policy_version` yields a new decision, never a mutated commit; failed alternatives never taint a survivor and never count as refutation.

## 4. Writer audit (ARCH-CRIT-001 inventory, current tree)

Every production writer that can emit a terminal outcome, and its routing status after this change (unchanged — none route through the kernel): `verify_root_cause_activity` verdict-state save plus success-shaped result (`activities.py` verify path, now typed-conflict on persistence failure); conclude-main `SUPPORTED→VERIFIED` promotion plus save; `ROOT_CAUSE_ESTABLISHED`/`ANSWERED` conclusion writes plus `save_conclusion`; the legacy conclude swallowed-save path; `finding_repository.save_finding_record` (`on_conflict_do_nothing`) and `save_conclusion` (upsert). The commit service is new code with no production callers; the only writers it adds are its own in-transaction projections, exercised by tests. Full authority routing remains staged for an explicit owner decision.

## 6. Test plan and exit mapping

Live suite `tests/integration/test_proof_publication_live.py` (gated `IAP_LIVE_TESTS=1`, dev `:5452`, dedicated tenant): derivation persist/reload round-trip; K6 root-premise change invalidates transitive dependents over the persisted graph while unrelated routes survive; K5 alternative survival with failed alternatives untainting; K12 same-derivation new-policy-version new-decision; K14 duplicate premise IDs rejected at construction plus distinct-ID same-content shared support; interleaved stale-version denial with zero partial writes; evidence-append denial; unadjudicated-conflict denial; happy-path commit with projections verified present. Exit maps to K5/K6/K12/K14/K8/K13/K15 on the production-shaped path; G5-formal remains open for the operator live leg and no gate closes on these tests alone.

## 7. Residuals (not closed by this change)

Loop-evidence appends racing a commit are not serialized (production write paths untouched by design). Validator-execution binding, predicate typing, and query-semantics coverage from the kernel phase remain staged. The full requirement ledger and authority routing remain staged for explicit owner decisions. Nothing here authorizes production wiring, rollout, or gate closure.
