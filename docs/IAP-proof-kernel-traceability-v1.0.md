## Status conventions

`PASS` means the cited executable test asserts the specified behavior for the tested inputs and boundary. It does not imply that untested cases, adjacent system boundaries, or end-to-end workflows are correct.

`PARTIAL` means the behavior is implemented or tested for a restricted subset, while identified cases or integration boundaries remain uncovered.

`PENDING` means relevant implementation or adjacent evidence exists, but the stated requirement has not yet been demonstrated by the required executable evidence.

`NOT IMPLEMENTED` means the capability is not implemented for the current stage. It must not be inferred from related heuristics, an advisory checker verdict, or a passing test suite.

`N/A` means the capability is explicitly outside the current stage by plan. This status does not imply that the capability is safe or complete.

`NOT MAPPED` (A–T only) means no executable test has been identified for that scenario in the kernel packages; legacy suites may exercise adjacent properties without constituting kernel evidence. Each NOT MAPPED letter carries an explicit rationale per owner decision 2026-10-24.

## Kernel enforcement boundary

The proof-kernel domain modules are implemented as pure modules and are not yet wired into an authoritative publication path. Adjacent application behavior has changed in diagnostics, retrieval telemetry, verifier-version routing, and onboarding. These changes must not be described as equivalent to kernel-enforced proof or publication guarantees.

## Checker independence

Import separation and producer-independence (monkeypatched producer, ignored self-acceptance, unapproved mapping abstention) are pinned by Component 2 tests.
