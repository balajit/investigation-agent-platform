## 1. System overview

IAP is a multi-tenant, durable-workflow incident-investigation platform: alert intake creates an investigation, Temporal orchestrates evidence gathering plus deterministic correlation plus LLM reasoning under budget and safety gates, and the platform persists timeline, transitions, hypotheses, findings, and conclusions with tenant isolation. Clients are SREs/operators, alerting systems, and external coding agents via REST and MCP.

## 2. Runtime composition (C1/C2 as-built)

One typed `AppContext` is built by `build_app_context` (`bootstrap/__init__.py:770-851`) from `load_application_config_from_env` (`infrastructure/configuration/config.py:783-846`) and preserved across API and worker lifecycles (`main.py:54-61`, `api/app.py:146`, `api/dependencies.py:2160-2176` fail-closed `TypeError` on non-`AppContext`). Lifespan order is Temporal client → buffered-dev (+evidence-gateway re-wire) → dev seed → job messaging (`main.py:196-212`); shutdown is idempotent (`dependencies.py:2179-2212`). Production never takes dev paths (guards at `main.py:74-75,122-123,180-181`, `buffered_dev.py:171-179` raises in prod); dev degrades explicitly with 503s (investigations router, health router) and bounded retries (API Temporal 8 attempts `main.py:90-101`, worker 10 attempts `worker.py:198-215`). Worker topology is three queues (investigation/indexing/analytics) with explicit concurrency bounds (`bootstrap/worker.py:62-125,266-316`) plus a schedule reconciler driven by `IAP_SCHEDULING_TENANTS` (`:139-173`).

Configuration is frozen Pydantic (`extra="forbid"`) with ~90 `IAP_*` env reads and `SecretStr` for all secrets (`config.py:20-577`); fail-closed production guards cover database URI, per-provider LLM keys, cursor signing key, and Azure/Muse required fields (`config.py:131-154,456-467,783-798`). Secrets arrive only via runtime env injection or secret-manager lookup through the `SecretStore` port (`ports/secrets/store.py`): the OpenBao adapter is the reference implementation with AWS/Azure/GCP extension adapters sharing the protocol, selected by `IAP_SECRET_STORE_PROVIDER` (`infrastructure/secrets/stores/factory.py`) and wired into the resolver chain at composition (`bootstrap/__init__.py`); file layers (`.env*`, then allowlisted YAML scalars in `infrastructure/configuration/layers.py`) never override runtime values and never carry secrets. Known gaps: leave-tracked `.env.local` decision recorded 2026-10-15, env-matrix landed, YAML hierarchy landed, `IAP_ENVIRONMENT` default mismatch.

## 5. API, MCP, providers, knowledge (C8–C11 as-built)

REST exposes 56 path operations across 15 router modules with typed `response_model` on all JSON routes (open contract guard `tests/unit/test_openapi_contract.py` has an empty untyped allowlist plus one SSE exemption); request bodies are router-local (deviation from the one-module-per-router input plan); tenant scoping plus admin auth plus quota 429 with `Retry-After` are enforced; pagination cursors are HMAC-signed and fail-closed; the error envelope is `{"error":{code,message,correlation_id}}` with `X-Correlation-ID` middleware. MCP exposes 4 tools (`search_runtime_evidence`, `get_evidence`, `investigate_trace`, `search_reference_docs`) over stdio (single-investigation scope from env, fail-closed UUID) and HTTP (per-request JWT plus investigation header via pure-ASGI middleware; the SDK standalone runner is banned because it bypasses auth, `mcp/server.py:221-223`); contract plus adversarial tests pin catalog parity. Providers register fail-closed and optional (Elasticsearch, Oracle/SQLcl MCP with per-server tenant allowlists, Postgres state backend as `postgres-primary`, PyGit2 ingest, Neo4j Layer 3, Kafka per-replica fan-out, S3/MinIO artifacts with local-dev adapter, LLM gateway plus streaming adapters); dynamic mapping resolves `NONE_REQUIRED` vs `FIELD` tenant scope per source (`domain/observability/mapping.py`). Knowledge uses write-once envelopes as source of truth with Mem0/Graphiti/Cognee default-off and envelopes-only degradation; all nine Part 11 gaps (input suspension, bulk intake, clustering, reference search, aggregate reports, chat SSE, jobs, credential providers, JSON recovery) are implemented behind registries with tenant scoping and quotas. Remaining items: router-local bodies and logger/typing residuals; operation count arithmetic, batch shape, and chat-guard fallback; artifact key scoping, MCP token typing, and Oracle/Mem0 runbooks.

## 6. Telemetry and coding standards (C3/C13 as-built)

Live telemetry is programmatic `structlog` (`api/app.py:24-41`, `JSONRenderer`) with `sanitize_extra` redaction (`api/errors.py:106`) enforced at the API layer; `config/logging.yaml` is unloaded dead config (console-only, `ConsoleRenderer`). Worker terminal paths use `logger.exception` consistently (exemplar discipline), shutdown logging is `%`-style with a names-only redaction contract (`dependencies.py:2215-2237`), and no secret values appear in sampled log calls. Against the required record shape the platform is partially sufficient: stage plus exception plus stack are present, but `function`/`line` keys, top-level `tenant_id`/`investigation_id` on worker failure extras, stable `event` keys outside startup/shutdown/composition, and `error_type`/`data` attributes are systematically missing, and worker extras can be dropped by the formatter split. Coding standards verified: per-file `getLogger(__name__)`, `X | None` typing with zero `Optional[`, no suppression, frozen Pydantic config/MCP/API schemas; violations to fix are raw-dict activity inputs, intelligence-port tenant scope, router-local bodies, f-string logger calls, and outbox/MCP logger gaps.

## 12. Boundary access logging (2026-10-17)

Every external API request logs its request line + sanitized query params + response summary (`status_code`, `duration_ms`, `response_class`, `response_bytes`, `response_streamed`) + the response JSON body truncated to `IAP_ACCESS_LOG_BODY_CHARS` (4096) with a marker (`api/app.py` correlation middleware; non-JSON bodies log size-only markers; streaming bodies are captured via iterator wrap and logged on completion). Bodies pass through `sanitize_extra` (secret keys redacted); `IAP_ACCESS_LOG_BODY=false` keeps summary fields only. Internal worker processing is untouched.

Log pipeline (`infrastructure/telemetry/logging.py`): `StructuredJsonFormatter` (timestamp/level/logger/message + service/code metadata, active OTel trace/span injection, exception envelope, ALL non-reserved stdlib `extra` merged — this replaces the structlog `ProcessorFormatter`, which silently dropped stdlib extras) and `DateSeqRotatingFileHandler` (active `{app}_{DDMMYY_HHMMSS}.log`, `_v1…_vN` cascade on size/date rollover; an `IAP_LOG_FILE` `.log` path contributes parent dir + stem). `IAP_LOG_APP_NAME` names the app for directory-style paths.

## 14. Reprocess versioning + budget multiplier (2026-10-17)

`POST /investigations/{id}/reprocess {mode, budget_multiplier?, reason?}` — terminal rows are never mutated. `RESTART_FRESH` always mints a new version (fresh request copy, no artifacts); `RESTART_CONTINUE` on terminal originals mints a new version and copies artifacts (evidence re-keyed + fingerprints re-salted around the tenant-wide uniqueness constraint, provenance re-pointed; hypotheses re-IDed with `VERIFIED` demoted, supporting refs remapped, assessments cleared; conclusions/findings stay in `metadata.prior_runs`). `RESTART_CONTINUE` on active rows 409s. Disposition matching/linking is bypassed by construction (`skip_disposition`; lineage in metadata only, no graph links). `budget_multiplier` N in [1, 10] (reprocess-only, 422 otherwise): iterations/tool-calls/evidence/hypotheses scale, `max_llm_tokens = min(xN, 1M)` absolute, iterations saturate at domain `le=100`; effective limits persist in metadata and the worker prefers them over profile overlay; token ledger resets per version (prior spend archived). Approval seam `require_budget_approver` is permissive today (recorded in `metadata.budget_approval`) with a shaped 403 for future role gating. Live proof: CONTINUE x5 completed with `effective_limits` applied, approval recorded, 12 rows, zero links.

## 16. Similar-past-investigation disposition (2026-10-16, TO_DO_LLM §2)

Every create is dispositioned against similar past runs deterministically, pre-run (`application/investigation/disposition.py`, fail-open to fresh). Matching: exact `code_issue_fingerprint` (reused error-intake identity) then near-text (typed `path:`/`sym:`/`word:` signatures, overlap coefficient, 30-day retention, bounded scan). Case matrix: active → `DUPLICATE_OF`, no new run (record closes `CANCELLED`, structurally unstartable); terminal success → re-verification pass (evidence/code/log/probe citations re-resolved, new HIGH/CRITICAL contradictions checked) → `CONFIRMED` serves cached as duplicate or `STALE` opens seeded `FOLLOW_UP_OF`; abstention/cancelled → seeded fresh with prior limitations (`RELATES_TO`); failed → `RETRY_OF`; text-similarity alone never duplicates (`POSSIBLY_RELATED` + fresh run). Links (`DUPLICATE_OF`/`FOLLOW_UP_OF`/`RETRY_OF`/`POSSIBLY_RELATED` alongside `RELATES_TO`) written only by the disposition step into `evidence_relationships` (`investigation:<uuid>` nodes), surfaced as `links` on detail and `disposition` on create responses. O5 companion: "not returning/missing" complaints seed existence-check-first planning. Restart versioning (§14) bypasses this entire path by construction. #30 operator rule (codified 2026-10-18): identical reruns MUST use `POST .../reprocess {RESTART_FRESH}` — identical fresh creates correctly CANCEL as `serve_cached`, and the create response now carries a `hint` saying so. Suppression is the correct behavior, not a bug.

## 18. Shareable code evidence (2026-10-17, G6)

Code evidence is repository-scoped reference data, not investigation-scoped observations. `evidence.lifecycle_scope` marks the split (`reference`: `SOURCE_CODE`, `COMMIT_HISTORY`; everything else `observational`); `evidence_bank_interest(tenant, investigation, evidence_key)` records which runs banked interest in a canonical row. Save path: fingerprint conflict with another investigation's reference row records interest and reports `shared` instead of silently dropping (same-holder conflicts stay `deduplicated`); batch stays constant-query (bulk insert + one holder-map + one interest insert). Hydration (`find_by_investigation_id`) unions owned + interest-joined rows, which automatically extends citation binding. Purge reassigns reference rows owned by purged investigations to remaining interested runs (or deletes when unreferenced); observational rows cascade as before. API: `GET …/evidence/sharing` marks shared rows with interested investigations. Reprocess CONTINUE reuses sharing (observational copies still re-salted as new observations). Migration 019. Live proof: identical re-read in a second investigation → `shared`, hydrates, marked.

## 66. Reasoning failures degrade, they do not fail (review H7/T7, 2026-10-30)

A reasoning step that cannot complete used to return `success=True, reasoning_unavailable`, which Temporal never retried and the workflow turned into `FAILED/UNKNOWN` with no conclusion, even after many good turns. The review's transient/dead line is now enforced, with one classifier: `classify_provider_failure`. `activities/common.classify_reasoning_failure` only maps its result onto four reasoning outcomes, and the coordinator (`application/investigation/reasoning.py`) stamps the kind on the unavailable decision (`metadata.failure_kind`, plus `retry_after` for a throttle).

| Kind | Source | Behavior |
|---|---|---|
| `transient` | timeout, outage, rate limit (`ProviderTimeout`, `ProviderUnavailable`, `ConnectionError`, `RateLimitException`, sniffed 429/timeout text) | `reason_activity` raises a retryable `ReasoningProviderTransient` so Temporal retries; a throttle's `retry_after` becomes the retry delay, clamped to 60 s. If retries exhaust the workflow catches the `ActivityError` and ends with `reasoning_provider_unavailable:*`. |
| `blocked` | first-party `CredentialProviderError`, `ProviderNotConfiguredError`, no gateway configured | typed result; terminal reason `provider_blocked:*`, which concludes through the existing deferred handoff. |
| `model_output` | schema-invalid or empty output after the bounded hidden resample | typed result; terminal reason `reasoning_model_output_invalid:*`. A transport error during a resample is classified as transient, not blamed on the model. |
| `other` | anything unclassified | typed result; terminal reason `reasoning_unavailable:*`. |

`conclude_investigation_activity` degrades every one of these (and `defer_gathering_invalid`, which had the same FAILED/UNKNOWN ending as its sibling `defer_repair_budget_exhausted`) to an `INSUFFICIENT_EVIDENCE` conclusion with `root_cause=None`, zero confidence, a limitation that names the reasoning failure rather than a verification miss "within budget", and a reason-specific next check (a different model or prompt for bad output, restore the provider for an outage). The banked evidence is untouched. The one case that stays `FAILED` is a transient outage that exhausted its retries with nothing banked: no evidence judgement is possible, and the run is stamped with the stable code `REASONING_UNAVAILABLE` instead of `UNKNOWN`. The terminal reasons and kinds are named in `application/worker/reasoning_failure.py`, a stdlib-only module so the workflow sandbox can import it.

The hidden resample is still the existing bounded, byte-identical one; varying it (H6) is a separate item. The shared classifier cannot tell a sniffed third-party 401 from an outage, so such a message is retried a bounded number of times and then degrades.

## 67. Reasoning quality: varied resample, checkability floor, failed-group re-fetch, D6 evidence cap (review H5/H6/H8, 2026-10-30)

**Loop versions lv3 and lv4.** `domain/investigation/loop_version.py` gains `lv3` (H5 floor, H8 re-fetch) and then `lv4` (current, the D6 evidence cap below); each includes everything earlier. Both are routed with `loop_version_at_least(metadata, "lv3")` on the entity's recorded pin: a run pinned lv2 keeps the old behavior, a new or unmarked run follows the current version. The lv3 rules and the lv4 cap only add retrieval (or withhold an early abstention); none can publish a verdict.

**H6 - the hidden resample varies, covers every malformed class, and sums usage** (`application/investigation/reasoning.py`). The two hidden resamples used to re-send a byte-identical request. Each now appends a corrective hint that names the failed schema fields (or the allowed action vocabulary, or the defer_gathering shape) and never a value the model emitted. Coverage widened from schema and one-action errors to every decision-validation class: defer_gathering shape, non-object, disallowed `action_type`, non-object `action.parameters` (`is_resamplable_decision_error`). A transport error is still not model noise and fails immediately. The call budget is unchanged (one call plus two resamples). `llm_usage` is now the sum over every attempt, including when the decision ends unavailable, and the typed unavailable result carries it. Not version-pinned: it changes only the request text of a single reason step and no stored shape.

**H5 - checkability floor** (`checkability_floor_reason`, `ReasoningCoordinator._apply_checkability_floor`, lv3). After claim coverage, a claim the model labelled NOT_CHECKABLE is re-typed CAUSAL when its statement asserts a causal mechanism or observable failure (cause, because, leads to, results in, throws, times out, exhausts, deadlock and similar) or when the model bound evidence to it (an opinion-only claim cites none). Re-typing errs toward checkable: a wrongly re-typed opinion costs a retrieval and faces the normal gates. The effect is that D6 (`_should_force_conclude_not_checkable`) no longer forces a zero-evidence CONCLUDE because of a mislabelled causal claim. The count by reason is recorded in `decision.metadata["checkability_floor"]`. Decided, not implemented: a floor on code identifiers or paths. A symbol or path in a claim does not make it falsifiable ("OrderServiceHandler is the best-designed handler" names real code and is still pure taste), so forcing it checkable produces an expensive INCONCLUSIVE (fetch, fail to verify, withdraw) where an honest abstention costs nothing, with the same terminal honesty at a higher price. The two floor triggers already cover the verdict-relevant cases: the causal-mechanism trigger catches would-be verdict claims and the cites-evidence trigger catches mislabeled grounded claims. This exclusion is deliberate. Reopen condition: if `metadata["checkability_floor"]` and the not-checkable rate ever show NC-with-identifier claims at high volume where verification would have succeeded (the exclusion costs correct verdicts, not just turns), revisit. An opinion that ships inside `root_cause` (L15) is not a floor problem: re-typing the taste claim only routes it to a verification it will fail. That hole is downstream, in the verdict assembly (H4 follow-up in the ledger).

**H8 - a failed cited group has a re-fetch route** (`VerificationEngine.failed_cited_group_ids`, `build_claim_gaps(..., failed_cited_group_ids)`, verify activity, lv3). A cited claim group used to be repair territory only, so a DEFINITION that cited a range read whose window missed the symbol ended INCONCLUSIVE with nowhere to go. When the taken verdict is not VERIFIED, the verify activity now re-verifies each cited, checkable, targeted group over the rows it cites (the same per-group gate `enforce_group_conjunction` uses; a cited DEFINITION or CALL_EDGE group with no bound row counts as failed) and passes the failures to the gap builder, which emits them as gaps tagged `reason="cited_gate_failed"`. The existing smallest-fetch carrier, builders, coverage stamps and per-kind caps consume them unchanged. The gap feed exists only under claim-binding cbv2 and cbv3, so under the default cbv1 this is dormant until H1's default is revisited.

**H5 remainder - D6 may not abstain before evidence was attempted** (`_d6_decision`, `_d6_cap_enabled`, `_should_force_conclude_not_checkable(..., cap_enabled=)`, `_is_gathering_action`, lv4). Loop version `lv4` (current; includes lv3 and lv2) adds one rule: the opinion-only fast path (D6) does not force CONCLUDE while the run has banked zero rows AND dispatched no gathering fetch. The invariant is "no abstention-for-lack-of-evidence before attempting evidence", so it covers turn 0 and any pathological never-banked later turn without special-casing either. Once the loop has tried (any gathering action dispatched, or any row banked) an all-NOT_CHECKABLE turn abstains as before, so L13's retrieval-light honest abstention stays reachable after one attempt. A blocked turn does not conclude; the cascade proceeds to gather. The two decisions stay separate: the existing not-checkable match is computed first and unchanged, then the cap is a distinct `if matched and no evidence attempted: do not force`. The workflow routes the call site through `_d6_decision`, which returns `(fire, blocked_by_cap)`. Gathering actions are every `ActionType` except FORMULATE_HYPOTHESIS, VERIFY_HYPOTHESIS and CONCLUDE (a unit test pins the literal set to the enum); the fetch counter increments when an action is dispatched, whether or not it banks rows. Routing is `loop_version_at_least` on the pin the workflow input carries: lv2 and lv3 pins keep the old behavior and an unmarked run follows lv4.
