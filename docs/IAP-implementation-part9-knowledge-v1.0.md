## Facts (current platform)

**Elastic evidence path.** `AsyncElasticAdapter` (`infrastructure/evidence/runtime/elastic.py`, 319 lines) owns query construction, provider bounds (`ELASTIC_MAX_HITS=200`, 7-day window, 20 keyword terms, 10 services), HMAC cursors, evidence mapping, OTel spans. All remediation-prompt defects confirmed verbatim: hard-coded `CURSOR_HMAC_SECRET` (line 48), cursor bound only to tenant/app (no query fingerprint), invalid cursor → silent page-one fallback, `except Exception` in decode, raw cursor in logs, `get_runtime_evidence(tenant_id, evidence_id)` with synthetic `uuid5("elastic-fetch:…")` investigation, platform-UUID vs ES-`_id` round-trip break, over-broad fetch pattern `logs-{tenant}-*-*`, `datetime.now(UTC)` timestamp fabrication, `_id`-as-`normalized_query_hash`, `{**src}` attribute pass-through, hard-coded `INTERNAL` classification. `ElasticIncidentBridge` (`infrastructure/evidence/logs/elastic_bridge.py`, 96 lines) delegates to the adapter, fixed `limit=100` with no completeness signal, `sqlglot.parse_one`, lower-cased unqualified table names, no dedup, no evidence refs.

**MCP today is outbound-only.** `infrastructure/evidence/mcp.py` (`McpEvidenceAdapter`) is a client calling external `search_logs`/`run-sql` tools — not a server. No `src/investigation_agent_platform/mcp/` package exists. `mcp==2.2.0` is installed; v1 `FastMCP` is gone — the v2 API is `from mcp.server.mcpserver import MCPServer` with `tool`/`add_tool`, `run_stdio_async`, `run_streamable_http_async`, `streamable_http_app` (mountable in the existing FastAPI app).

**Reuse points (all verified).** Auth: `api/tenant.py` (`VerifiedIdentity`, JWT-verified, `X-Tenant-ID` dev-only). Config: `infrastructure/configuration/config.py` (`EvidenceConfig`, `_evidence_config_from_env()`, fail-closed precedent). Exceptions: `domain/common/exceptions.py` (no cursor/provider-timeout types yet). Evidence store: `SqlAlchemyEvidenceRepository` — `evidence_key` unique per tenant (`uq_evidence_tenant_key`), `get_by_id(tenant, evidence_id)`, `find_by_investigation_id`, `(tenant, fingerprint)` dedup, `payload_json` holds full `Evidence`. **Schema mismatches requiring migration.** `Evidence.observed_at: datetime` required (domain + `EvidenceORM.observed_at nullable=False`); `EvidencePage.next_cursor` max 256 (signed cursors exceed it); `RuntimeEvidenceRequest.limit le=500` vs provider ceiling 200, keywords max 50 vs 20, `cursor max_length=256` vs 4096 needed.

## Decisions locked

1. **Timestamps nullable (Q1).** `Evidence.observed_at` and `EvidenceFreshness.observed_at` become `datetime | None`; missing/invalid `@timestamp` → `None` + data-quality signal, `retrieved_at=now` always. Requires an Alembic migration on `evidence.observed_at`. Matches the target-arch schemas (already nullable there).
2. **Platform-owned evidence IDs (Q2).** ES hit → qualifies as evidence → platform mints UUID, persists the row (`evidence_key` + `payload_json` provider ref = the mapping, no new table). `get_evidence` resolves only through `get_by_id(tenant, evidence_id)` + investigation-ownership check; raw ES `_id` never accepted as input; unknown/cross-scope → `EVIDENCE_NOT_FOUND` with no disclosure. Phase 1 confirmed the write path: `application/worker/activities.py` persists result batches with `investigation_id` via `save_batch`; the Phase 5 service must do the same or round-trip fails by design.
3. **Dual transport (Q3).** stdio (`run_stdio_async`, local agent) + Streamable HTTP (`streamable_http_app` mounted in `api/app.py`, reusing `get_verified_identity`). One tool/application layer; stdio context from env/config-bound identity with `IAP_ENVIRONMENT` dev/prod parity. **Cursors: hard-invalidate** pre-remediation tokens on deploy (version bump, old unversioned → `INVALID_CURSOR`), documented in deploy notes.
4. **Placement.** New server at `src/investigation_agent_platform/mcp/` (top-level — avoids collision with the outbound `infrastructure/evidence/mcp.py`, which stays untouched). Exactly 3 tools: `search_runtime_evidence`, `get_evidence`, `investigate_trace`, with the exact 2020-12 schemas/descriptions/annotations from the target arch. Harden first (Phases 1–4), then build MCP (never on known-unsafe cursor/provenance behavior).

## Phase 6 record (MCP server, DONE 2026-09-28)

Schemas are SDK-derived from annotated handler signatures (single source of truth, no drift) with strict all-required output models. Handlers close over `InvestigationServices` (no `services` schema params exist). Auth: pure-ASGI middleware (shared JWT verification + validated investigation header; 401/400/403 before dispatch) for Streamable HTTP; env-bound single scope for stdio. Strict-arguments middleware rejects unknown properties at protocol tier (`-32602`); semantic failures return the 9-code `{"error": {...}}` envelope. `McpConfig` added (`IAP_MCP_*`). Recorded deviations from the blueprint: (1) SDK wraps union returns in a `{"result": {...}}` wire envelope (framework-determined, contract-tested); (2) MCP `services` accepts up to 20 items while the domain/provider ceiling stays 10 (11–20 fail as `INVALID_REQUEST` at the domain tier); (3) `CURSOR_EXPIRED`/`INCOMPLETE_EVIDENCE` codes reserved (expiry shares `INVALID_CURSOR`; truncation is in-band completeness); (4) trace derivation flows through the gateway (single sanitized evidence path) via the `TraceTelemetryDerivationPort`, not a parallel adapter call. Residuals: production HTTP deployment wiring (`mount_mcp` + `main()` provided), CORS allowlist for `X-Investigation-ID`, `SEARCH_LOGS` profile capability, gateway search correlation plumbing, stdio single-investigation scope.
