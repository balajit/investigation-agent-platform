# DES-tenant-telemetry-config v1.0

- Status: ACCEPTED
- Satisfies: REQ-investigation-loop-reengineering-v1.0 (C3, C4, G4)
- Implements: ADR-BOUNDARY-001 (service scope); IAP-investigation-architecture-v2.0 (feedback edges)

## 1. Schema

Tenant operator-scope file, a list of named endpoint blocks. Each block: `name` (unique, required), `url` (full base URL, required, no embedded credentials), auth group (`user`+`password` basic pair, `api_key` encoded-key string, `bearer_token` static token, or the `oauth_token_url`/`oauth_client_id`/`oauth_client_secret` client-credentials trio; precedence `api_key` > `oauth` > `bearer` > `basic` > none, selected kind logged by name at boot), `timeout` (default 30s), `pattern` (default `logs-*`; may be comma-separated — search passes it as one comma-joined index expression, fetch accepts any matching segment), `services` (service names homed here, required), TLS (`verify_certs` default true, optional `ca_certs` bundle path; `ca_certs` + `verify_certs = false` aborts), `managed_by` (`manual` default, `auto` for discovery-written). Each secret field accepts a `fernet:<token>` envelope (key from `IAP_ES_FERNET_KEY`, env only) or the two-part `fernet:<cipher>:<token>` in-field form (plaintext stays out of the file, but file readers can decrypt — access-control-level, not real secrecy; a bare `cipher` key is rejected); undecryptable/empty secrets abort load. Invariant: every service maps to exactly one endpoint (configure-time check, fail closed).

## 2. Storage, precedence, secrets

File in tenant operator scope is source of truth (owner-readable only, never in repo). Env overrides per endpoint (`IAP_ES_<TENANT>_<NAME>_{URL,USER,PASSWORD,API_KEY,TIMEOUT,PATTERN}`). Secret handling follows the existing SecretStr/redaction standard.

## 3. Wiring

One adapter, tenant-resolved connections per request: service → home endpoint → that endpoint's auth/pattern/timeout. Global default applies only when the tenant configures nothing. Selector, mapping profiles, and profile authorization untouched.

## 4. Validation and failure

Configure-time per endpoint (reachable → auth → pattern matches → mappings parse → sanity read), fail closed. Runtime: required-fetch on a dead endpoint → BLOCKED_ON_TELEMETRY with ERROR-level structured logs (no credentials), backoff + heartbeat, then terminal DEFERRED with resume pointer; the condition stays open until recovery or acknowledgment. Code-side-only work never blocks on telemetry. Warning level is reserved for degraded-optional; required-evidence failure is always ERROR.

## 5. Implementation note (Phase A, 2026-10-29)

Mechanics (no spec change, recorded so the wiring is explicit): one `AsyncElasticAdapter` instance holds a boot-built `TenantTelemetryRouter` (`infrastructure/evidence/runtime/tenant_telemetry.py`); selector, gateway, mapping profiles, and profile authorization are untouched — routing happens inside the adapter. Search homing keys are `profile.id` (the gateway's `application_id`) plus the profile's declared service names as aliases; with no profile the request's service filter is the identity signal. The GET-fetch path carries no profile, so the stored index selects the endpoint by falling under exactly one endpoint's attested pattern (zero/ambiguous matches fail closed). A routed request uses the endpoint's connection, index pattern (replacing the mapping-derived pattern; the mapping still governs the field contract), and timeout; `execution_metadata.endpoint` names the serving deployment (null = global). The pattern may be comma-separated: search passes it to Elasticsearch as one comma-joined index expression, fetch accepts a stored index matching any segment — required for data streams, whose hits carry the concrete backing index (`.ds-<stream>-*`) rather than the searched stream name (proven live 2026-10-29: fetch of a `.ds-logs-n-…` row resolves the home endpoint). Extensions beyond §1–§3, all fail-closed: adapter may serve with no global client when a router exists (unknown-tenant requests then refuse loudly); per-endpoint request timeout must strictly exceed the provider query timeout (same coherence rule as the global adapter); `api_key` wins when both auth forms are present, a half-configured basic pair aborts load, auth-less endpoints are allowed; an `IAP_ES_*` override naming no file-defined endpoint aborts load (file stays source of truth for endpoint existence). Deferred to Phase C (needs reason-workorder machinery): the `BLOCKED_ON_TELEMETRY`/`WAITING`/`DEFERRED` error codes, backoff + heartbeat, and resume pointers — Phase A delivers ERROR-level logs with endpoint name (never credentials) plus the existing typed errors (`ProviderNotConfigured`/`ProviderTimeout`/`ProviderUnavailable`). File-log default interplay: file-log is the default route only when no Elastic serves at all (global or tenant-routed); otherwise `elastic-primary` stays default, preserving pre-tenant behavior exactly when no tenant configures anything.

## 6. Verification and onboarding surfaces (Phase A, 2026-10-29)

Verification lives in the platform (`application/onboarding/telemetry_verification.py`: `verify_tenant_telemetry` over loaded configs, `verify_tenant_telemetry_from_dir` for dir-based runs), sharing the single client factory bootstrap uses. Both onboarding surfaces invoke it: the `onboard verify-telemetry` CLI (offline, dir-based, human/`--json` output) and `POST /tenants/{id}/onboarding/telemetry:verify` (inline endpoint declarations, no server filesystem). Drivers stay thin: `scripts/verify_telemetry.sh` is env-layering + exec only. No standalone verification scripts; the earlier `/tmp` scratch checkers were deleted. Sample template: `config/telemetry.conf.sample` (the loader only reads the exact `telemetry.conf` filename, so samples can never load).

Recorded direction (not yet designed): endpoint declarations are destined to be captured as part of the ApplicationProfile for an operator/customer rather than sidecar files. When that lands, this file's §2 source-of-truth rule and the loader move with it; the router, adapter resolution, and verification flow are source-agnostic (they consume `TenantTelemetryConfig`) and should not change.

Auth construction is single-sourced in `TelemetryEndpoint.connection_kwargs()` (the bootstrap factory delegates): one unit-tested mapping from endpoint fields to `AsyncElasticsearch` kwargs, so basic/bearer/api-key/TLS wiring cannot drift between call sites. OAuth client-credentials (`oauth_token_url`/`oauth_client_id`/`oauth_client_secret` + optional `oauth_scope`) is implemented with a caching `OAuthTokenProvider`: the token is fetched once per validity period (the provider-stated `expires_in`, never assumed — absent/non-numeric/non-positive aborts), reused until within 300s of expiry, refreshed under a lock so concurrent requests trigger one grant, and injected per ES request via `client.options(bearer_auth=...)` on the shared transport (pooling unaffected). Fetch failures fail closed and loud (typed errors, ERROR logs naming tenant/endpoint/token host, never secrets); expired tokens are never served; `oauth` + static `bearer_token` together abort (two sources, one credential). Proven live 2026-10-29 against a stub IdP: one grant for two searches, correct grant shape, real rows returned.
