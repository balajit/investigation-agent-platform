## 3. Configuration and startup (C1/C2 as-built)

Configuration is frozen Pydantic (`extra="forbid"`) with ~90 `IAP_*` env reads and `SecretStr` secrets (`infrastructure/configuration/config.py:20-577`), fail-closed production guards (database URI, provider keys, cursor signing key, Azure/Muse fields), layered file loading (`.env` plus `.env.<environment>`, then allowlisted non-secret YAML scalars for unset names via `infrastructure/configuration/layers.py`, always losing to runtime env), and a chained `env://`-then-`secret://` resolver with production fail-closed behavior (`infrastructure/secrets/resolver.py:33-159`); secret values arrive via runtime injection or the `SecretStore` adapter chain (OpenBao reference plus AWS/Azure/GCP extensions selected by `IAP_SECRET_STORE_PROVIDER`, `infrastructure/secrets/stores/`), and no code reads `.env` files for secrets. Composition builds exactly one `AppContext` (`bootstrap/__init__.py:770-851`) shared by API (`main.py:54-61`, `api/app.py:146`) and worker (`bootstrap/worker.py:128-136`), wires Temporal then buffered-dev (plus gateway re-wire) then seed then job messaging (`main.py:196-212`), degrades explicitly outside production, and shuts down idempotently. Deviations from the ideal are filed, not hidden: tracked `.env.local` (TO_DO-001), missing manager backend (TO_DO-002), missing env-matrix (TO_DO-003), dead YAML loader with drifted defaults (TO_DO-004/005 in `TO_DO_001.md`), and the `IAP_ENVIRONMENT` default mismatch (TO_DO-005).

## 4. Observability and coding standards (C3/C13 as-built)

Live telemetry is programmatic structlog JSON (`api/app.py:24-41`) with API-layer `sanitize_extra` redaction; `config/logging.yaml` is unloaded dead config. Worker terminal paths use `logger.exception` consistently and shutdown logging is `%`-style with names-only redaction, but the required record shape is only partially met: `function`/`line` keys, top-level worker `tenant_id`/`investigation_id`, stable `event` keys beyond startup/shutdown/composition, and `error_type`/`data` attributes are systematically missing, MCP failures log at `info` with nested IDs, and worker extras can be dropped by the formatter split. Standards verified include per-file loggers, `X | None` typing, no suppression, and frozen schemas; violations are filed as strict Pydantic activity inputs, tenant-first port signatures, router-local request bodies, f-string logger conversion, and outbox/MCP logger residuals (TO_DO-006–010 in `TO_DO_002.md`; TO_DO-016–020 in `TO_DO_004.md`).

## 5. Domain, workflow, and persistence (C4–C7 as-built)

Aggregates (`Investigation` with UUID, OCC `version`, `code_issue_fingerprint`; `Fact`/`FactType`; `Evidence` fingerprint-required with redaction manifest and tier-2 invariant plus 12 relationship types; `Hypothesis` 6 statuses; `Finding`/`InvestigationConclusion` 4 statuses; `ApplicationProfile` with `secret://`/`env://` refs only) enforce frozen typing with zero infra imports; ports are `runtime_checkable` and tenant-first (modulo TO_DO-017). The Temporal `RunInvestigationWorkflow` drives create → contextualizing → investigating → correlate/hypothesize/verify loop → concluding → completed/failed/cancelled with `PAUSED`/`AWAITING_INPUT` states and `COMPLETED/FAILED→INVESTIGATING` reopen via knowledge intake; resume restores investigation plus profile plus evidence plus timeline; cancel persists the transition; halt is signal-based. Persistence is async SQLAlchemy with RLS, OCC, outbox-for-domain-events (timeline/transitions are the per-mutation audit), revisioned profiles, UUID evidence keys, and fingerprint dedup. Deviations are filed: idempotency-key coverage (TO_DO-011), audit lossiness and actor (TO_DO-012), duplicated transition graph (TO_DO-013), timeline tenant predicates and `FORCE RLS` (TO_DO-014), batch N+1 (TO_DO-015), retention (TO_DO-023), and Fact hardening (TO_DO-024).
